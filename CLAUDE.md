# Premiere Assistant — описание проекта

## Цель
Универсальный ИИ-ассистент внутри Adobe Premiere Pro (позже — After Effects).
Это не «плагин с кнопками», а панель-чат, где автор может:
- спросить что угодно о монтаже/звуке/анимации/Premiere и получить ответ с учётом ЕГО проекта;
- поручить действие («проверь громкость, нужно −14 LUFS», «раскрась клипы по типу», «разложи звук по сабмиксам») — ассистент сам выполняет его в проекте;
- делать долгие задачи в фоне, продолжая монтировать.

Приложение должно расти: каждая новая возможность = новый инструмент (tool), который ИИ умеет вызывать. Ядро, чат и база знаний общие для всех хост-приложений.

Автор: монтажёр и разработчик (Vite + React, TypeScript, GitHub, Vercel). ОС: **Windows**. Общение и интерфейс — на русском.

## Архитектура

```
┌────────────────────────────┐        WebSocket (localhost)        ┌─────────────────────────────────┐
│ UXP-панель в Premiere      │ ◄─────────────────────────────────► │ Локальный помощник (Node, TS)   │
│ React + TS                 │                                      │ • агентный цикл с Claude API    │
│ • чат, подтверждения, лог  │   помощник шлёт вызовы host-tools →  │ • реестр инструментов           │
│ • host-tools: выполнение   │   панель выполняет и возвращает      │ • local-tools: ffmpeg, файлы,   │
│   через Premiere DOM API   │   результат ←                        │   веб-поиск, фоновые задачи     │
└────────────────────────────┘                                      │ • база знаний (рецепты/пресеты) │
                                                                    │ • API-ключ в .env (не в панели) │
                                                                    └─────────────────────────────────┘
```

- **Два режима «мозга»** (переключаются в «Настройки → ИИ»):
  - **Встроенный (по умолчанию)** — агентный цикл работает прямо в панели (`src/agent/embedded.ts`), ничего запускать не нужно. Ключ вводится один раз в панели и хранится в `uxp.storage.secureStorage`. Поддерживаются OpenRouter, Gemini, Ollama (fetch; если UXP не умеет читать поток по частям — ответ читается целиком).
  - **Через помощника** — отдельная программа на Node (WebSocket), ключ в `.env`. Нужен для будущих функций, которые UXP не умеет (запуск ffmpeg и т. п.).
- Общий код агента — в `packages/core/src/agent/` (AgentSession, провайдеры OpenRouter/Ollama/Gemini, проверка входа, системный промпт); им пользуются и панель, и помощник. Claude-провайдер (Anthropic SDK) — только в помощнике.
- Чтобы плагин был в Premiere всегда (без UDT после каждого перезапуска) — установить `.ccx` (UDT → ⋯ → Package или `update-plugin.cmd`; установка — UnifiedPluginInstallerAgent).
- **Автообновление:** GitHub Actions (`.github/workflows/release.yml`) на каждый push в main собирает панель (версия `0.2.<run_number>`, репозиторий — `PANEL_UPDATE_REPO`) и публикует релиз с `index.js` и `premiere-assistant.ccx`. Панель при запуске проверяет `releases/latest`, по кнопке скачивает `index.js` в папку данных плагина и запускает его вместо встроенной версии (`src/update/*`, в manifest — `allowCodeGenerationFromStrings`). Откат — «Настройки → Обновления». Новые картинки/иконки и изменения manifest требуют переустановки `.ccx`.
- **Панель** — UI и выполнение операций с проектом (Premiere API доступен только внутри UXP).
- **Помощник** — «мозг»: ведёт диалог с моделью, решает, какие инструменты вызвать, исполняет локальные инструменты сам, а host-инструменты пересылает в панель.
- **API-ключ к ИИ никогда не попадает в код панели**: он вводится пользователем (встроенный режим — `secureStorage`) или лежит в `.env` помощника.
- Позже помощник можно частично вынести на Vercel; в v1 всё локально.

### Инструменты (tools)
Каждый инструмент — отдельный модуль с единым контрактом:

```ts
interface ToolDef {
  name: string;               // "premiere.read_timeline", "audio.measure_loudness"
  description: string;        // для модели: что делает и когда использовать
  inputSchema: JSONSchema;
  runsIn: "host" | "helper";  // где исполняется
  mutates: boolean;           // меняет проект/файлы? → требуется подтверждение
  run(input, ctx): Promise<unknown>;
}
```

- Инструменты регистрируются автоматически из папки — новый файл = новая возможность, без правки ядра.
- Префиксы по хосту: `premiere.*`, позже `ae.*`; общие: `audio.*`, `files.*`, `web.*`, `knowledge.*`.

## Правила безопасности (обязательно)
1. Любой инструмент с `mutates: true` выполняется **только после подтверждения** пользователя в панели (показать, что именно изменится).
2. Перед крупной операцией — сохранить копию проекта (или убедиться, что изменения откатываются через Undo одним шагом; проверить, что даёт API).
3. Код, сгенерированный моделью «на лету», никогда не выполняется без показа пользователю и подтверждения. Удачные скрипты можно сохранить как новый инструмент — тоже с подтверждением.
4. Ничего не удалять с диска без явного подтверждения.
5. Не блокировать Premiere надолго: массовые правки таймлайна — пачками, тяжёлая работа — в помощнике.

## Стек
- **Панель**: UXP plugin для Premiere Pro 25.6+, manifest v5, React + TypeScript, сборка Vite (или рекомендованный Adobe шаблон — сверить с официальными starters).
- **Помощник**: Node.js (LTS) + TypeScript, WebSocket (`ws`), Anthropic SDK, ffmpeg.
- **Модель**: на выбор через `AI_PROVIDER` в `.env` — OpenRouter (бесплатные модели, автовыбор умеющих инструменты; по умолчанию), Ollama (локально), Gemini (REST, бесплатный тариф) или Claude (Anthropic SDK, платно). OpenRouter и Ollama — один модуль `openaiCompat.ts` (формат OpenAI Chat Completions). Оба с tool use; имена моделей — в `.env`. Провайдеры — `packages/helper/src/providers/` за общим интерфейсом `Conversation` (история в родном формате провайдера, наружу — шаги «текст + вызовы инструментов»); агентный цикл, подтверждения и инструменты общие.
- **Монорепозиторий** (pnpm или npm workspaces):

```
/packages
  /core          — общие типы, контракт ToolDef, протокол сообщений панель↔помощник
  /panel-premiere — UXP-панель + host-tools для Premiere
  /helper        — сервер, агентный цикл, local-tools, база знаний
  /panel-ae      — (позже) панель + host-tools для After Effects
/knowledge       — рецепты, пресеты, заметки (Markdown/JSON), растёт со временем
```

## Важно про Premiere UXP API
- API ещё догоняет старый ExtendScript: часть операций может отсутствовать (например, обсуждались razor/split, перемещение аудиоклипов). **Перед реализацией инструмента проверить в документации, что нужный метод существует**, и не выдумывать методы.
- Документация: https://developer.adobe.com/premiere-pro/uxp — Premiere DOM API (секвенции, дорожки, клипы, маркеры, проект), UXP API (файлы, сеть, shell).
- Изучить официальный sample-плагин `premiere-api` (Adobe) как образец вызовов.
- Сетевой доступ панели к `localhost` должен быть разрешён в manifest (permissions → network). Проверить формат по документации.
- Если операцию сделать нельзя — инструмент честно возвращает «не поддерживается API» и предлагает ручной путь.

## Настройка окружения (Windows)
1. Premiere Pro 25.6+: Preferences → Plugins → **Enable developer mode**.
2. Установить **UXP Developer Tool** (через Creative Cloud) — загрузка/перезагрузка/отладка панели.
3. Node.js LTS, git.
4. ffmpeg: `winget install Gyan.FFmpeg` (проверить `ffmpeg -version` в новом терминале).
5. `.env` в `/packages/helper` (создаётся сам из `.env.example` при первом запуске): `AI_PROVIDER`, ключ и модель выбранного провайдера (`OPENROUTER_*`, `OLLAMA_*`, `GEMINI_*`, `ANTHROPIC_API_KEY`/`CLAUDE_*`), `HELPER_PORT`. `.env` — в `.gitignore`.
6. Пути на Windows — через `path`, без хардкода `/`; учитывать пробелы и кириллицу в путях.

## План

### Этап 1 — каркас (v0)
- Монорепо, общий протокол сообщений (JSON по WebSocket: `user_message`, `assistant_delta`, `tool_call`, `tool_result`, `confirm_request`, `confirm_response`, `task_progress`).
- Помощник: WebSocket-сервер, агентный цикл с Claude, реестр инструментов, стриминг ответа.
- Панель: чат (стриминг), карточка подтверждения действий, лог задач, индикатор подключения к помощнику.
- Скрипт запуска помощника одной командой.
- **Критерий готовности**: в панели внутри Premiere пишу «привет» — получаю ответ от модели.

### Этап 2 — первые инструменты
- `premiere.read_timeline` — активная секвенция: дорожки, клипы (имя, тайминги, медиафайл, метка), маркеры. Только чтение.
- `audio.measure_loudness` — измерение Integrated LUFS, LRA, True Peak через ffmpeg (`ebur128` / `loudnorm` в режиме анализа) для указанного файла. Первая версия: пользователь экспортирует микс (или выбираем файл), позже — автоматический экспорт аудио секвенции, если API позволяет.
- `web.search` — поиск в интернете (через встроенный в API веб-поиск или отдельный сервис — решить по документации Anthropic).
- **Сценарий проверки**: «проверь громкость, цель −14 LUFS, true peak −1» → ассистент измеряет, объясняет результат и даёт конкретные шаги (сабмиксы, лимитер на мастер, Loudness Normalization при экспорте).

### Этап 3 — действия с проектом
- ✅ Покраска таймлайна (вкладка «Авто» + инструменты `premiere.read_timeline`, `premiere.color_timeline`, `premiere.get_color_rules`, `premiere.update_color_rules`). Категории: музыка, SFX, голос, звук с камеры, видео, графика, корректирующие слои; распознавание по имени дорожки/клипа/файла, расширению и длительности (`src/automation/classify.ts`); правила в localStorage панели, «доучиваются» из чата. **Ограничение API:** у клипов на таймлайне нет метода смены цвета — меняется Label элемента проекта (`ProjectItem.createSetColorLabelAction`), одной транзакцией (один Ctrl+Z). **Номера меток:** в Premiere 16 меток (Caribbean — третья), а в `Constants.ProjectItemColorLabel` Caribbean нет — при последовательных 0…14 используем настоящий порядок Premiere (`labelTable()` в `automation/timeline.ts`); «Авто → Диагностика цветов» показывает фактические номера. Похоже, уже лежащие на таймлайне клипы цвет файла не наследуют (проверяется) — поэтому есть «Выделить» по категории (`premiere.select_clips`, `TrackItemSelection.createEmptySelection` + `Sequence.setSelection`): пользователь назначает цвет одним действием.
- ✅ Быстрые действия с выделенными клипами (вкладка «Пресеты» + `premiere.transform_clips`): вписать, заполнить, по центру, сбросить, выровнять 3×3 с отступом — через параметры Motion (`createKeyframe` + `createSetValueAction`); отразить — эффект Horizontal/Vertical Flip (`VideoFilterFactory`). Единицы Position/Anchor (доли кадра или пиксели) определяются по текущему значению; размер исходника — из `Metadata.getProjectColumnsMetadata` («Video Info»). Клипы с ключевыми кадрами пропускаются.
- ✅ Анимации выделенных клипов (вкладка «Пресеты» → «Анимации» + `premiere.animate_clips`, `premiere.list_animations`): влёт/улёт в 4 стороны, наезд/отъезд, появление/исчезновение, свои пресеты (`presets/animations.ts`, localStorage). Эффект Transform (`AE.ADBE Geometry2`, переиспользуется) с моушн-блюром (Use Composition's Shutter Angle = выкл, Shutter Angle 360), ключевые кадры в медиа-времени клипа (getInPoint/getOutPoint), плавность Bezier; шаги — отдельными транзакциями, как в примере Adobe. Проверить в Premiere, что время ключей совпадает с началом/концом клипа.
- Раскладка/маршрутизация аудио, маркеры по найденным проблемам (тихие места, клиппинг) — по мере поддержки API.
- Очередь фоновых задач с прогрессом в панели.

### Этап 4 — база знаний и рост
- `knowledge.search` / `knowledge.save` — рецепты и пресеты автора; ассистент сначала смотрит туда.
- Сохранение удачного сгенерированного скрипта как нового инструмента (с подтверждением).

### Этап 5 — After Effects
- `panel-ae` на том же core/helper, свои `ae.*` инструменты. AE UXP пока в бете — сверять доступность API.

## Интерфейс панели
- Стиль Apple, тёмная тема (как Premiere) с лёгким фиолетовым оттенком. Фирменный цвет — фиолетовый: кость #9F18EC, фон логотипа #7A1CF0 → #4B0CB4 → #22045E. Токены — в `packages/panel-premiere/public/styles.css`.
- Логотип — кость: `public/icons/logo.svg` (белая кость на фиолетовой плитке), `bone.svg` (фиолетовая кость), `dark.svg`/`light.svg` — монохромные иконки панели для меню Premiere.
- Шапка: логотип + вкладки-иконки в «таблетке» (**Чат · Авто · Пресеты · Задачи · Настройки**; подпись у активной и во всплывающей подсказке), справа — действие вкладки. Внизу — строка статуса: связь и активная секвенция слева, провайдер и версия справа. Новая крупная возможность может получить свою вкладку.
- Иконки интерфейса — PNG из `design/icons/*.svg` (рендер: `node design/render-icons.cjs`): UXP показывает SVG-картинки на чёрном фоне и без градиентов.
- Цвет акцента выбирается в настройках (фиолетовый — фирменный, плюс синий, розовый, зелёный, оранжевый): CSS-переменные `--accent*`, `src/theme.ts`.
- Плитки (`.tile`) — «стеклянные» кнопки для пресетов и быстрых действий; разделы сворачиваются.
- Экран приветствия перед первым использованием: что умеет ассистент + живой чек-лист готовности (помощник, API-ключ, проект). Повторно — из «Настройки → Показать приветствие».
- Пресеты: выравнивание 3×3 с отступом Край/5%/10% и плитки «Клип» работают; «Мои пресеты» — пока «Скоро».
- UX по эвристикам Нильсена: статус всегда виден (пилюля в шапке, «печатает…», счётчик задач), пользователь управляет (Стоп, Отклонить, Новый чат), предотвращение ошибок (подтверждения, неактивные кнопки), узнавание вместо припоминания (подсказки-примеры), понятные сообщения об ошибках с действием. Закон Якоба: привычные паттерны (пузыри как в «Сообщениях», сгруппированные списки как в «Настройках»).
- Ограничения UXP: только flex (без grid и `gap`), без `backdrop-filter`, CSS-анимации ненадёжны (анимация — через JS); у градиентов и теней всегда есть запасной сплошной цвет; кнопки — `div` (нативный `<button>` в UXP почти не стилизуется).
